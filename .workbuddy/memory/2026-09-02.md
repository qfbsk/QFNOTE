# 2026-09-02

## QFNOTE 主题同步 bug 修复（主窗/小窗 ball 不同步）

- 根因：小窗 `ball` 用 `WebviewWindowBuilder.visible(false)` 创建，JS 实际加载很晚（缩小显示时才真正加载），启动时主窗 `render_ready` 用 `init-theme` 广播给小窗，小窗监听器还没注册 → 错过广播，停在写死 `theme0`，只能手动切主题触发 `sync-theme` 才对齐。
- 启动主题机制：`theme_next.txt` 存"下一次主题号"，`render_ready` 读出后 `persist_theme` 推进 +1（0..5 循环），所以每次启动颜色不同（故意轮换，非随机）。手动切主题时 `sync_theme` 也会重置 `theme_next.txt`。
- 修复：后端加 `get_current_theme` 命令（内部 `resolve_init_theme` 用 `theme_ready: Mutex<bool>` 一次性守卫，主窗或小窗谁先调谁算一次，避免各算一次错位）；小窗 `dist/mini.html` 加载完 `invoke('get_current_theme')` 自己取主题并应用，删除旧的 `init-theme` 广播监听（死代码），保留 `sync-theme`（手动切）。主窗逻辑未动。
- 构建环境：本机无 Rust 工具链，用 `RUSTUP_DIST_SERVER=https://rsproxy.cn` 装 minimal；cargo 依赖缓存 `~/.cargo/registry` 约 1.6G（之前编过）；`tauri build` 走 tuna 镜像拉余下包；MSVC link.exe 在（VS2022 Build Tools），Tauri v2 打 MSI 不需要 WiX。改动仅 lib.rs + dist/mini.html 时增量编译约 4 分钟。
